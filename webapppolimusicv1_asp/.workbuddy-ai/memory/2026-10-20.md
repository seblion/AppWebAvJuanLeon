# 2026-10-20 — PoliMusic (clon Spotify ASP clásico)

Generación completa del sitio tipo Spotify con ASP clásico (VBScript) + SQL Server.

- Esquema: BDD_PoliMusic.sql (UTF-16; convertir con Python a UTF-8 para leerlo). Login SQL: usr_polimusic / Politecnica1 (db_owner). 9 tablas (TBL_SONG, TBL_USER [USER_TYPE 0/1], TBL_ALBUM, TBL_ARTIST, TBL_TRACKLIST, TBL_PLAYER, TBL_PLAYLIST, TBL_PLAYLIST_SONG, TBL_CATALOG).
- Usuario sembrado `username1` guarda SHA1("12345678") en PASSWORD → el login compara texto plano OR `CONVERT(VARCHAR(64),HASHBYTES('SHA1',@p),2)` en SQL.
- Assets reales: solo `SongFiles/bensound-adventure.mp3` + 6 imágenes de playlist + 2 de usuario. La BD referencia rutas inexistentes (~/albumImages/..., ~/songFiles/dreams.mp3...). Solución: `RutaRecurso()` en includes/conexion.asp mapea ~/… → SongFilesAndImages_resources/… con FSO.FileExists y fallback (canciones sin MP3 → bensound-adventure.mp3; albumN/artistN → playlistN.png).
- Archivos creados: index.asp (hero + "Song List" + álbumes/artistas/listas + reproductor), login.asp (Session.Abandon anti-fijación), logout.asp, api_reproducir.asp (PLAY por AJAX/JSON), admin/{canciones,artistas,albumes}.asp (CRUD con RequiereAdmin + ParEntero/ParTexto parametrizados + eliminación en cascada manual dentro de transacción), includes/{conexion,header,footer,reproductor}.asp, css/styles.css (negro/azul), js/{app,player}.js (validados con node --check), README.md (despliegue IIS).
- Convención del proyecto: RUTA_BASE="/" en conexion.asp (asume sitio publicado como raíz en IIS); todas las consultas usan ADODB.Command parametrizado; salida escapada con EscaparHTML.
- Pendiente del usuario: ejecutar BDD_PoliMusic.sql en SSMS y publicar en IIS (instrucciones en README.md).

## 2026-10-20 (turno 4) — CAUSA RAÍZ del HTTP 500 ENCONTRADA Y CORREGIDA

- Síntoma: TODAS las páginas que incluyen `includes/conexion.asp` daban error genérico IIS; `hola.asp` (sin includes ni Option Explicit) funcionaba 100% (ASP, sesión, FSO, SQLNCLI11 con `Server=localhost`). El usuario tiene la app en `C:\inetpub\wwwroot\webapppolimusicv1_asp` (URL http://localhost/webapppolimusicv1_asp/).
- **Causa raíz: `includes/conexion.asp` contenía `<%@ Language=VBScript CodePage=65001 %>` Y `Option Explicit`, duplicados porque cada página principal ya los lleva. Al fusionarse el include, VBScript rechaza la compilación → HTTP 500.100 genérico en toda página que lo incluya.**
- **Fix: los includes NUNCA deben llevar directivas `<%@ %>` ni `Option Explicit` (convención PERMANENTE del proyecto). `Option Explicit` se declara una sola vez en la página principal.** Verificado con grep: solo páginas principales tienen ambos; header/footer/reproductor/conexion quedaron limpios.
- Nota del entorno del usuario: editó `Const DB_SERVIDOR` a `"localhost\SQLSERVER2026"` (instancia nombrada) — RESPETAR esa edición. hola.asp usa `Server=localhost` hardcodeado (instancia default, que también respondió OK).
- Pendiente: que el usuario recargue `paso2.asp` / `index.asp` tras el fix. Si la instancia nombrada no tiene BDD_PoliMusic, aparecerá la página de diagnóstico de AbrirConexion con el detalle por proveedor.

## 2026-10-20 (turno 5) — Cadena COMPLETA de 4 bugs de compilación, todos corregidos

 Método decisivo: script `C:\Users\sebas\AppData\Local\Temp\pm_fuse.py` que emula la fusión de includes de ASP, extrae el VBScript y lo compila con el motor REAL (cscript = mismo VBScript.dll que IIS) → errores con línea exacta. Las 11 páginas .asp AHORA COMPILAN.

Bugs encontrados (todos provocaban el HTTP 500 genérico en toda página que incluyera includes):
1. **`<%@ %>` + `Option Explicit` duplicados** en includes/conexion.asp (las páginas principales ya los llevan) — corregido turno 4.
2. **Mi propio comentario de fix contenía `<%@ ... %>`**: el preprocesador ASP cerraba el bloque de código a mitad del include → "Se esperaba una instrucción". REGLA: nunca escribir `<%`/`%>` en comentarios ni cadenas.
3. **`Dim _scriptName, _segundaBarra`**: VBScript NO permite identificadores que empiecen con guion bajo → "Carácter no válido". Renombrados a scriptName/segundaBarra.
4. **`Dim paginaActual` en header.asp colisionaba con la función `PaginaActual()`** de conexion.asp (VBScript es case-insensitive) → "Nombre redefinido". Renombrado a `nomPagina`.

- Restricción del entorno: mi shell NO tiene permisos de escritura en `C:\inetpub\wwwroot\webapppolimusicv1_asp` (el usuario despliega como admin). El usuario debe copiar includes/conexion.asp e includes/header.asp desde el workspace al despliegue tras cada fix.
- Validación: `python pm_fuse.py index.asp login.asp ...` sobre el workspace → "OK: compila" en las 11 páginas.
- Nota: hola.asp servía como control (no incluye nada → siempre funcionó); eso permitió aislar que el fallo estaba en el include desde el turno 3.
